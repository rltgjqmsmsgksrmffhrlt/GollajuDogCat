## 2. 변경 상세

### 2-1. 별점 현실화 (J자형 분포)
- 5점이 압도적으로 많고, 1점이 그다음, 2~3점이 가장 적은 이커머스 리뷰의 전형적 분포로 조정.
- 52건을 낮은 별점으로 변경 (4→3 18건, 4→2 1건, 5→2 9건, 5→1 24건). 시드 고정.
- `products.avg_rating`과 `validation` 시트를 실제 리뷰 집계에 맞게 재계산 (36개 상품 모두 PASS).
- 별점이 바뀐 리뷰의 본문·설문 답변도 별점에 맞춰 수정 (불만 내용: 기호성/소화/피부·모질/알러지/급여 편의성 중 1개).
- 3점 리뷰는 "반응은 보통이에요. 다만 처음보다 먹는 양이 조금 줄었어요."처럼 순한 표현 사용.

### 2-2. 설문 문항 구조 (실제 리뷰 작성 폼 기준)

| 문항 | 필수 여부 | 선택지 → 저장 값 |
|---|---|---|
| 기호성 `PALATABILITY` | 필수 | 안 먹어요=NEGATIVE / 보통이에요=NEUTRAL / 잘 먹어요=POSITIVE |
| 급여 편의성 `FEEDING_CONVENIENCE` | 필수 | 불편해요=NEGATIVE / 보통이에요=NEUTRAL / 편해요=POSITIVE |
| 소화·배변 `DIGESTION` | 선택 | 나빠졌어요=NEGATIVE / 그대로예요=NEUTRAL / 좋아졌어요=POSITIVE |
| 피부·모질 `SKIN_COAT` | 선택 | 위와 동일 |
| 체중·활력 `WEIGHT_VITALITY` | 선택 | 위와 동일 |
| 알러지 `ALLERGY` | 선택 | **없었어요=POSITIVE / 있었어요=NEGATIVE** (NEUTRAL 미사용) |

- `WEIGHT_VITALITY` 문항을 신규 추가 (리뷰 287건 × 1행, id 1436~1722).
- 선택 문항은 확률적으로 미응답 처리 (`review_answer = NULL`, 리뷰당 6행 구조는 유지).
- 알러지 매핑(없었어요=POSITIVE)은 가정입니다. 백엔드가 다르게 저장한다면 바꿔야 합니다.

응답 분포 (변경본, 287건 기준)

| 문항 | NEGATIVE | NEUTRAL | POSITIVE | NULL | 응답률 |
|---|---|---|---|---|---|
| PALATABILITY | 23 | 41 | 223 | 0 | 100% |
| FEEDING_CONVENIENCE | 6 | 123 | 158 | 0 | 100% |
| DIGESTION | 8 | 77 | 109 | 93 | 68% |
| SKIN_COAT | 5 | 75 | 72 | 135 | 53% |
| WEIGHT_VITALITY | 5 | 86 | 40 | 156 | 46% |
| ALLERGY | 7 | 0 | 104 | 176 | 39% |

원본은 5개 문항 전부 100% 응답이었고 POSITIVE 91%, NEUTRAL 9%였으며 NEGATIVE와 NULL이 없었습니다.

### 2-2-1. 응답 확률 가정
선택 문항 응답률은 실제 통계가 아닌 가정값입니다.

| 문항 | 기본 응답률 |
|---|---|
| 소화·배변 | 65% |
| 피부·모질 | 50% |
| 체중·활력 | 45% |
| 알러지 | 35% |

- 건강 고민 태그와 관련된 문항(예: 체중 고민이면 체중·활력)은 90%로 상향.
- 피부·모질, 체중·활력은 사용 기간이 14일 미만이면 응답률을 절반으로 낮춤.
- 4~5점 리뷰 답변 분포: 소화 좋아졌어요 55%, 피부 45%, 체중·활력 40%, 급여 편의성 60%, 알러지는 모두 없었어요.

### 2-3. 리뷰 본문 (쿠팡 후기 스타일)
- 구매 계기 → 사용 기간 → 기호성 반응 → 설문 항목 언급 → 팁 → 배송·가격 한마디 → 재구매 의사 순으로 문장을 조합.
- 단문 30% / 중문 40% / 장문 30%를 섞어 길이를 다양화, 끝에 "ㅎㅎ", "^^", "!!"가 일부 붙음.
- 본문에 언급된 항목은 반드시 응답이 있는 항목이고 답변 값과 일치 (전수 검사 불일치 0건).
- 본문의 "N일"은 모두 `usage_period` 값과 일치.
- 모든 본문이 `review.text` 컬럼 한도 `varchar(255)` 이내 (최대 253자). 폼 표시 한도는 300자이지만 DB 한도 기준으로 맞춤.
- 이름 끝 글자 받침 유무에 따라 조사 처리 ("호두가", "콩이가", "하루는" 등).

### 2-4. 사용 기간
- 폼의 자유 입력(예: 12일)을 반영해 3~120일로 재생성: 둥근 숫자(7/10/14/15/20/21/30/45/60/90) 40% + 로그정규 분포 60%.

### 2-5. 시트 이름 / README
- `stock_events` → `stock_movements` (스키마 문서의 테이블명에 맞춤).
- `README` 시트에 별점 분포, 리뷰 질문 유형, 설문 응답 규칙 3행 추가.

## 3. 변경 전후 예시

원본 (5점, 4점)
> 하루 반응은 좋은 편이에요. 사료 냄새가 너무 강하지 않아요. 조금 더 급여해보고 재구매할 것 같아요.
> 호두가 처음부터 잘 먹었어요. 사료 냄새가 너무 강하지 않아요. 전체적으로 만족해서 재구매하려고 합니다.

변경본 (5점)
> 강아지 먹일 사료 찾다가 구매했어요. 주변에서 추천받아 사봤는데 후기대로 괜찮네요. 6일 먹여본 후기예요. 호두가 냄새 맡자마자 달려와서 먹어요. 변이 단단해지고 냄새도 덜해요. 소분이 쉬워서 관리하기 좋아요. 처음엔 조금씩 섞어서 급여하는 걸 추천해요. 배송도 빨라서 좋았어요. 가격 대비 양이 넉넉해요. 강추합니다!

변경본 (1점)
> 별이에게는 맞지 않았어요. 기존에 없던 가려움이 생겼어요. 재구매 의사 없습니다. (이후 구매 계기·사용 기간·아쉬운 점 문장이 덧붙은 형태)

## 4. 재현 방법
원본 엑셀에 아래 스크립트를 순서대로 실행합니다 (모두 시드 고정, 이미 적용됐으면 변경 없이 종료).

```bash
python scripts/mock_rebalance_review_ratings.py   # 별점 J자형 재조정 + 본문/답변 수정
python scripts/mock_add_weight_vitality.py        # WEIGHT_VITALITY 문항 추가
python scripts/mock_refine_review_answers.py      # 필수/선택 규칙, 미응답, 장문 본문, 사용기간
```
`stock_events` → `stock_movements` 시트 이름 변경은 스크립트 없이 직접 수정했습니다.

## 5. 한계 및 확인 필요 사항
- 응답률, 답변 분포, 문구는 현실을 모사한 가정값이며 실제 서비스 통계가 아닙니다.
- 알러지 `없었어요`를 POSITIVE로 저장한 것은 가정입니다.
- `image_url`은 파일명만 들어 있어 실제 사용 시 스토리지 URL 접두사가 필요합니다.
- 별점 조정과 본문 재작성 이후 리뷰 이미지(98개)와 리뷰의 연결은 그대로지만, 본문이 이미지 내용을 설명하지는 않습니다.
