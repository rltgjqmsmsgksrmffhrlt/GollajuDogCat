## 장바구니 이탈률(A 40%) vs 추천상품 CVR(A 3.3%) 양립 불가 계산

`02_simulate_events.py`의 `PARAMS`를 확정하기 전 검증한 계산입니다.

세션 유입 경로 비중: 추천 45% / 검색·GNB(direct) 55% (고정값)

전체 목표 구매율(=1-이탈률) = 0.45 × (추천 경로 CVR) + 0.55 × (direct 경로 구매율)

**A그룹**: 목표 구매율 0.60 (이탈률 40%), 추천 CVR 0.033 고정
```
0.60 = 0.45 × 0.033 + 0.55 × x
x = (0.60 - 0.01485) / 0.55 = 1.064   ← 100% 초과, 수학적으로 불가능
```

**B그룹**: 목표 구매율 0.455 (이탈률 54.5%), 추천 CVR 0.0321 고정
```
x = (0.455 - 0.45×0.0321) / 0.55 = 0.801   ← 가능
```

### 결론 및 처리

- B그룹은 direct 경로 구매율을 약 80~91%로 설정해 목표 이탈률 범위(52.8~56.1%)를
  실제로 달성함 (검증 결과 54.4%).
- A그룹은 수학적으로 40% 이탈률을 달성할 수 없으므로, direct 경로 구매율을 실질적
  상한(약 95~100%)으로 설정해 최대한 근접시켰고, 실제로는 56.6%로 근사.
- 이는 **원본 계획서의 두 지표가 서로 다른 벤치마크 출처**(전자상거래 일반 카트
  이탈률 벤치마크 vs 반려동물 카테고리 CVR 벤치마크)를 사용했기 때문으로 추정.
  실제 서비스 데이터로 검증할 때도 이 두 지표의 모집단 정의가 다르다는 점
  (이탈률 = 전체 장바구니 세션 대비, CVR = 추천 상품 상세 진입 세션 대비)을
  감안해야 함.

## 공통 속성표 중복 제거 이력

작업 중 아래 두 가지 패턴의 중복이 발견되어 제거함:

1. **동일 raw 필드가 다른 이름/설명으로 중복 등록**
   - `session_start`가 "세션 시작 시간"(공통)과 "세션 시작(활성 유저)"(서비스 충성도)
     두 번 등록되어 있었음 → 후자 삭제, 필드 설명에 "전체 비교기능 사용률의 분모로도
     사용됨" 메모만 추가.

2. **raw 이벤트와 그 이벤트를 조건부로 집계한 파생 지표가 별도 행으로 혼재**
   - `complete_purchase (source:recommendation)`(raw 필드)와 "N일 내 추천 퍼널
     재구매 완료"(`purchase (source=recommendation)`로 표기된 파생 지표)가 별도
     행으로 존재 → 파생 지표 행 삭제, raw 필드의 측정 방법/고려사항에 계산 로직 흡수.
   - `reaction_complete`(raw 필드)와 "퍼널 단계 이동(입력시작→완료)"(같은 태그를 쓰는
     파생 지표) → 동일하게 파생 지표 행 삭제.

**원칙**: 태그명(이벤트명) 컬럼이 같은 두 행이 있다면 하나는 raw 필드 정의이고
다른 하나는 그 필드로 계산하는 지표일 가능성이 높음. 이 경우 지표 계산 로직은
raw 필드 행의 "측정 방법"/"고려사항"에 흡수하고 별도 행을 만들지 않는다.
