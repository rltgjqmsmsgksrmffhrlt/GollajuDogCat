### 3.3.3 Sprint 3 회고 (근거: 09/11 팀장 주간 미팅 + 데일리 스크럼, 09/16 기준 잠정)

**Keep**

- **데이터 수집 계획서를 명확히 작성**해 가상 운영 데이터가 계획대로 산출되었고, 기능명세서도 거의 마무리되었다. (PM, 09/11)

**Problem**

- PD는 일정 압박으로 **주말 작업이 필요**했고 부담이 특정 직군에 집중되었다. (PD, 09/11)
- **결원이 많아 협업이 어려웠다.** (AI, 09/11) PM도 주중 2일 결원이 있었다. (09/11)
- FE가 **디자인 시스템 → UI 디자인 → API 명세** 순의 선행 산출물에 연속으로 묶여, 2주차 중반(09/15)까지 화면 구현 착수가 지연되었다.
- **API 명세의 수정 주체가 FE·BE로 이중화**되어 있어 09/11에야 일원화 협의가 이루어졌다.
- **AI↔BE 인터페이스 명세 공유가 09/17로 밀리면서** BE의 AI 연계 기능 개발이 스프린트 마지막 이틀에 집중되었다.
- 기능명세서 해석 관련 질문(일반 목록 조회와 추천 조회의 분리 여부, 상품 상세 배너 정적 이미지의 반환 주체 등)이 주간 미팅까지 이월되었다. (BE, 09/11)
- 직군별 이슈·블로커가 **각 회의록에만 흩어져 있어** Phase 3 산출물 작성 시점(09/14)에 소급 취합해야 했다.
- 인터뷰 피드백에서 지적된 것처럼 **직군별 전문용어가 타 직군에 그대로 전달**되어 의사결정 속도가 떨어지는 구간이 있었다. (09/16)

**Try**

- 인터페이스(명세·계약) 변경은 **단일 오너를 지정하고 PR 단위로 동기화**한다 — API 명세는 BE, 디자인 핸드오프는 PD가 오너.
- 의존 요청은 **"무엇을 / 누구에게 / 언제까지"** 형식으로 기한을 명시해 기록한다. (09/14 AI API 기한 합의 방식을 표준화)
- 블로커 트래킹 표를 **스프린트 시작 시점부터 상시 운영**하고, 데일리 스크럼에서 상태만 갱신한다. (스프린트 종료 후 소급 취합 금지)
- 선행 산출물 의존이 있는 과업은 **착수 가능한 최소 단위(와이어프레임·목데이터 기준)를 병행 진행**해 대기 시간을 줄인다.
- 공가·부재는 **전주 금요일 주간 미팅에서 사전 공유**하고 주차 계획에 반영해, 주말 작업으로 메우는 구조를 줄인다.
- 타 직군 대상 공유 시 **전문용어에 1줄 설명을 병기**한다.
