## 2. ⚠️ 재생성 전에 반드시 읽을 것

### 2.1 재생성은 "값 보정"이 아니라 "전부 다시 뽑기"입니다

`02_simulate_events.py`의 난수는 하나의 스트림을 순차적으로 소비합니다. **중간의 난수 호출 하나만 값이 바뀌어도, 그 뒤의 모든 추첨이 통계적으로 독립인 새 값으로 이어집니다.**

실제로 겪은 일: 상품 선택 필터의 버그 하나(2.3절)를 고쳤더니 —

| | 수정 전 | 수정 후 |
| --- | --- | --- |
| 이벤트 | 169,707건 | 170,560건 |
| 주문 | 345건 | 381건 |
| 가설1 장바구니 전환 | A 3.8% &gt; B 3.6% | A 3.63% **&lt;** B 3.82% |

**A/B 우열 방향까지 뒤집혔습니다.** 버그와 무관한 지표(Kaggle 실측 확률 기반)도 함께 바뀝니다.

→ **재생성했다면 문서·xlsx·아티팩트의 모든 수치를 다시 뽑아야 합니다.** 일부만 고치면 산출물끼리 어긋납니다.

## 3. 실험 설계 — 순서를 지키세요

### 3.1 올바른 순서

1. **효과크기(MDE)와 유의수준(α)을 먼저 정한다** — 데이터를 보기 전에
2. **필요 표본을 계산한다** — 목표 검정력(80%)을 넣어 역산
3. **그만큼 모은다** — 중간에 결과를 보지 않는다
4. **한 번 검정하고 그 결과를 받아들인다**

> **왜 순서가 중요한가**: "유의해질 때까지 표본을 늘려보자"는 반복하면 결국 우연히 유의한 지점에서 멈추게 됩니다(optional stopping). 미리 계산한 목표 n에서 **한 번만** 보는 것과는 통계적으로 완전히 다릅니다.

### 3.2 이 프로젝트의 확정 기준

| 항목 | 값 |
| --- | --- |
| 유의수준 | **단측 α = 0.10** (= P(A&gt;B) ≥ 90%) |
| 목표 검정력 | 80% |
| 표본 | **9,700명/군 (총 19,400명)** |
| 기간 | 90일 (일 신규 유입 약 216명) |

9,700명은 세 가설 각각의 설계상 기대효과를 80% 검정력으로 검출하는 데 필요한 값 중 **최댓값**입니다(가설1 7,895 / 가설2 3,906 / 가설3 9,679 → 가설3이 병목).

### 3.3 표본 계산 스크립트

```python
import math
from scipy.stats import norm

def required_n(p1, p2, z_alpha=1.282, power=0.80):
    """p1=대조군 기준치, p2=기대 처치군 값, z_alpha: 단측 .10=1.282 / .05=1.645 / 양측 .05=1.96"""
    return (z_alpha + norm.ppf(power))**2 * (p1*(1-p1) + p2*(1-p2)) / (p2-p1)**2

def achieved_power(n, p1, p2, z_alpha=1.282):
    se = math.sqrt(p1*(1-p1)/n + p2*(1-p2)/n)
    return norm.cdf((p2-p1)/se - z_alpha)
```

**유저 수로 환산할 때** — 지표마다 유저 1명이 만드는 표본량이 다릅니다. 이걸 놓치면 계산이 무의미해집니다.

| 지표 | 분모 | 유저 1명당 |
| --- | --- | --- |
| 가설1 구매전환율 | 진입 세션 | **5.45개** |
| 가설2 재구매 CVR | 추천 클릭 세션 | **2.45개** |
| 가설3 입력완료율 | 배송완료 알람 주문 | **0.062개** |

가설3은 가설1의 **1/88**입니다. 유저를 늘려도 가설3 표본은 거의 안 늘어납니다.

## 4. ⚠️ 효과크기는 퍼널 단계마다 곱해집니다

**이 프로젝트에서 실제로 냈던 계산 오류입니다.** `LIFT = +15%`는 **각 단계 확률**에 적용되므로, 여러 단계를 거치는 최종 지표에서는 효과가 곱해집니다.

| 가설 | 적용 경로 | 실제 효과크기 |
| --- | --- | --- |
| 1 구매전환율 | 추천 진입 세션(45%)에만 → **희석** | **+13.6%** |
| 2 재구매 CVR | 장바구니 ×1.15 × 구매 ×1.15 | **+29.8%** |
| 3 입력완료율 | 입력시작(0.18×1.15) × 입력완료(0.78×1.15) | **+32.2%** |

세 가설 모두 +15%로 계산했다가, 검정력을 가설2 45.6% / 가설3 23.3%로 **크게 과소평가**했습니다. 실제 값은 91.2% / 55.7%였습니다.

**검산법** — 설계상 기대값을 손으로 계산해 실측과 맞춰보세요.

```
가설3 B: 0.18 × 0.78         = 14.04%   (실측 13.97% ✓)
가설3 A: (0.18×1.15) × (0.78×1.15) = 18.57%   (실측 19.60% ✓)
→ 상대효과 +32.2%, "+15%"가 아님
```

**교훈**: 새 지표를 설계하면 **"이 지표는 LIFT가 걸린 단계를 몇 개 거치는가"**를 먼저 세어보세요.

## 5. 판정 규칙

### 규칙 1 (주 판정) — 베이지안 사후확률 P(A&gt;B) ≥ 90%

```python
import numpy as np
RNG = np.random.default_rng(20260909)   # 시드 고정 필수

def p_a_better(xa, na, xb, nb, draws=200_000):
    sa = RNG.beta(1 + xa, 1 + na - xa, draws)
    sb = RNG.beta(1 + xb, 1 + nb - xb, draws)
    return round(100 * float((sa > sb).mean()), 1)
```

**왜 이걸 쓰나**
- 표본 크기와 무관하게 작동 — 시간·세그먼트로 쪼갤 필요가 없어 저빈도 지표(가설3)에도 그대로 적용됩니다
- 출력이 의사결정 언어와 직접 연결 — "p=0.0066"보다 "A가 나을 확률 99.7%"

**임계값이 90%인 이유**: 무정보 사전분포에서 `P(A>B) ≈ 1 − 단측 p-value`이므로, 90%는 단측 α=0.10과 같고 3.2절 표본 계산 기준과 정확히 맞습니다. 95%로 올리면 필요 표본이 13,271명/군으로 늘어 현재 규모를 초과합니다.

> **중복 주의**: P(A&gt;B)와 단측 p-value는 사실상 같은 검정입니다. 둘을 별개 근거로 세지 마세요.

### 규칙 2 — 가드레일 (하나라도 걸리면 방향과 무관하게 보류)

| 지표 | 보류 기준 |
| --- | --- |
| NPS | 치료군이 대조군보다 5점 이상 낮음 |
| 장바구니→구매 이탈률 | 치료군이 5%p 이상 높음 |
| 상품상세 체류시간 | 치료군이 30% 이상 급증(혼란/버그 신호) |

### 규칙 3 — 다중비교: 가설당 주 지표 1개만 판정에 사용

90% 기준으로 7개 지표를 검정하면 **최소 1건이 거짓양성일 확률이 52%**입니다. Bonferroni(개별 98.6%)는 초기 단계에 과하다고 보고, 임상시험식 primary/secondary 지정 방식을 씁니다(주 지표 3개면 27%).

| 가설 | 주 지표 (판정용) | 보조 지표 (참고용) |
| --- | --- | --- |
| 1 | 구매전환율 | 장바구니 전환율 |
| 2 | 재구매 CVR | NPS, 30일 재구매율, 2회+ 구매 유저 비율 |
| 3 | 입력완료율 | 알람 확인율, 유효반응 비율 |

### 쓰지 않기로 한 것 — 주차별 방향 일관성

"13주 중 10주 이상 같은 방향"(이분포 부호검정 기준 우연 확률 4.6%)은 **참고용으로만** 씁니다. 표본을 13등분하면 각 주의 n이 1/13로 줄어 방향이 무작위로 흔들리기 때문입니다.

실제로 가설2는 검정력 97.9%로 가장 견고한데도 주차별로는 9/13주에 그쳤습니다. **효과가 약해서가 아니라 쪼개는 행위가 신호를 파괴한 것**입니다. 각 버킷의 사건 수가 양 군 각각 30건 이상일 때만 보조 근거로 인용하세요.

## 6. 지표 설계 — 분모를 잘못 잡으면 표본이 증발합니다

### 6.1 실제 사례: 60일 재구매율 → 2회+ 구매 유저 비율

| 측정 방식 | A | B | P(A&gt;B) | n |
| --- | --- | --- | --- | --- |
| 60일 재구매율 | 9.7% | 10.0% | **45.0%** ✗ | 62/40 |
| 2회+ 구매 유저 비율 | 0.57% | 0.32% | **99.6%** ✓ | 9,500/9,500 |

같은 "충성도" 질문인데 판정이 갈립니다. 60일 재구매율은 **"60일 관측창이 확보된 유저"**만 분모에 넣어 표본이 62/40건으로 쪼그라들었습니다. 분모를 전체 유저로 바꾸니 150배가 됐습니다.

**기간을 못 늘려도 측정 방식을 바꾸면 해결되는 경우가 많습니다.**

### 6.2 분모 선택 체크리스트

- [ ] **분모가 처치 이전에 결정되는가?** — "구매자 중 재구매율"처럼 분모 자체가 처치의 결과면 collider bias 위험이 있습니다. 무작위 배정된 전체 유저를 분모로 쓰면 안전합니다
  - 부득이 쓴다면 편향의 **방향**을 따져보세요. 예: A는 개인화로 148명을 추가 전환시켰고 그 한계 구매자들은 재구매 성향이 낮아 A의 비율을 끌어내립니다 → A가 그럼에도 높다면 보수적으로 안전
- [ ] **분모가 퍼널 하류에 있는가?** — 하류일수록 표본이 급감합니다(가설3: 유저당 0.062건)
- [ ] **관측창 조건이 붙는가?** — "N일 이상 관측된 유저"류 조건은 표본을 크게 깎습니다

### 6.3 어트리뷰션 주의

`complete_purchase`의 `source`는 **마지막 접점 하나로 덮어써집니다.** 비교 기능을 함께 쓰면 `comparison`으로 재태깅돼, 추천 기여 구매가 350건으로 집계됩니다(실제 추천 클릭 세션 내 구매는 397건, **12% 과소평가**).

→ 기능별 성과로 리소스를 배분하려면 멀티터치 어트리뷰션으로 로깅을 바꿔야 합니다. 지금은 "엄격 기준"과 "세션 내 실제 결제 기준"을 **둘 다 병기**하는 방식으로 대응하고 있습니다.
