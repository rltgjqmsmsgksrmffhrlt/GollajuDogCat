## 2. 현황 공유

### 🔸 데일리 스크럼

---

- 작업은 타팀의 진행도에 따라 완성을 기다리는 것이 아닌 진행중인 작업을 그 때 그 때 대응하여 진행하기로 결정
- **디자인 시스템 작업 with. PD**
    
    **0. 컴포넌트 변경사항은 피그마-업데이트 히스토리에 갱신.**
    
    **1. 브랜드, danger 버튼 글자색 접근성**
    
    brand 버튼은 #ff611d 배경에 흰색 글자, danger 버튼은 #ff0015 배경에 흰색 글자로 지정되어 있으나 현재 값으로는 일반 크기 글자의 접근성 기준인 4.5:1보다 대비가 낮게 나옴.(brand와 흰색은 약 3.01:1, danger와 흰색은 약 3.99:1)
    
    ➡️ PD에서는 버튼과 같은 라벨은 3:1로 진행해도 무관할 것으로 판단, danger는 다크모드에서 3:1 미만으로 나와 변경 예정. 변경 시 업데이트 히스토리에 기재
    
    **2. 특정 컴포넌트 이름이 붙은 색상 분류**
    
    03. semantic > bg에 스위치·별점·가격·반응 표시처럼 특정 컴포넌트 이름이 들어간 색상 12개가 있음. 현재 코드에는 이 색상들을 공용 색상으로 추가하지 않고 제외한 상태로, 04. component의 컴포넌트 전용 색상으로 정리 제안
    
    ➡️ 컴포넌트로 분리하는 것으로 확정
    
    **3. 변수 네이밍 확인**
    
    이 항목들은 현재까지는 사용되지 않으나, 디자인 시스템 정리를 위해 체크
    
    - success 관련 변수가 success가 맞는지, info로 변경되어야 하는지 확인 필요
    - icon/fill/static_black은 이름과 달리 라이트·다크에서 색상이 바뀌며 icon/fill/default와 같은 값을 사용하고 있음. 값이 잘못 연결된 것인지, 이름이 잘못된 것인지
    
    ➡️ success는 info로 변경, static_black 색상이 바뀌지 않도록 값 변경
    
    **4. 오탈자 수정**
    
    | **컬렉션** | **변수명** |
    | --- | --- |
    | 03. semantic | bg/postive_weak, bg/postive |
    | 03. semantic | text/body/postive_default, text/body/postive_strong |
    | 03. semantic | icon/stroke/postive |
    | 03. semantic | border/postive_weak, border/postive |
    | 04. component | badge/bg/postive_weak, badge/bg/postive |
    | 04. component | badge/border/postive |
    | 04. component | snackbar/icon_postive |
    - Price_fg_neutral_secondery → Price_fg_neutral_secondary
    - Information - callout > state=positve → state=positive
    
    ➡️ 오탈자 목록화하여 전달 완료
    
    **5. 버튼 크기 단계 정의**
    
    가이드에는 버튼 크기가 S 28px, M 32px, L 40px, XL 44px의 네 단계로 정의되어 있으나, 실제 버튼 컴포넌트에는 small, medium, large 세 단계만 있으며 각각 32px, 40px, 44px로 설정되어 있어 작업 기준 확인이 필요
    
    ➡️ 피그마를 기준으로 총 세 단계로 진행, 가이드 문서 변경 요청
    
    **6. 기본 색상과 연결되어 있지 않음**
    
    03. semantic > bg/accent dark만 다른 bg/* 변수들과 다르게 연결 없이 #fff로 하드코딩되어 있어 확인 요청
    
    ➡️ #fff → yellow/dark/500으로 변경
