#### 인프라

- 인프라 구축 내용
    
    안녕하세요. dev 브랜치에 Jenkins CI/CD 파이프라인이 적용됐습니다. 앞으로 서비스 코드 작업하실 때 아래 내용 참고 부탁드립니다. (인프라 클러스터가 올라와있을때만 해당 작업이 진행됩니다)
    
    1. PR 올리실 때 (dev 대상)
    
    PR 열면 자동으로 변경된 서비스만 감지해서 다음이 순서대로 돌아갑니다: 테스트 → 빌드 → Trivy 보안 스캔
    이 단계에서는 실제 배포(ECR push 등)는 안 일어납니다. 검증만 합니다.
    CRITICAL 등급 보안 취약점이 있으면 스캔에서 막혀서 PR 체크가 실패합니다 — 의존성 버전 문제일 가능성이 높으니, 실패하면 어떤 라이브러리 때문인지 로그 확인 부탁드립니다.
    
    1. dev에 머지되면
    
    위 과정(테스트/빌드/스캔)에 이어서 실제로 이미지가 ECR에 push되고, gitops-value 레포가 자동으로 갱신됩니다.
    ArgoCD가 그 변경을 감지해서 알아서 재배포합니다. 사람이 따로 배포 버튼 누를 필요 없습니다.
    여러 서비스가 한 PR에 걸려있으면 순차로 빌드됩니다(서비스 개수만큼 시간 소요).
    
    1. 알아두시면 좋은 것
    
    Dockerfile은 이제 미리 빌드된 jar를 담기만 하는 구조라, 서비스 코드/설정만 신경 쓰시면 되고 Dockerfile은 따로 안 건드리셔도 됩니다.
    Jenkins에서 수동으로 "Build Now" 눌러도 실제 배포(ECR push)는 안 되게 막아뒀습니다 — 실배포는 오직 dev에 실제 merge가 될 때만 일어납니다. 실수로 잘못 눌러도 안전합니다.
    
    Jenkins 콘솔 로그로 실패 원인 직접 확인 가능하시고, 접근 방법이나 그 외 궁금한 점 있으시면 언제든 DM 주시면 됩니다. (gitops task 파일에다가 jenkins id/비번 확인할 수 있는 명령어 넣어두었습니다) jenkins으로 ci를 구축했다보니 매번 ci가 돌지는 않고 서버가 다시 올라와있을때만 이를 확인해서(2분 간격으로) 최신 dev기준으로 ci가 돕니다
    
    감사합니다!!
