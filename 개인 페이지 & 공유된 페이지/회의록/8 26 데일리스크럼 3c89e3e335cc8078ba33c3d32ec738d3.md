#### AI 통합 데이터 스키마 정리

- 문서 기반 백엔드가 할 일
    
    **① 새로 만들 테이블 4개**
    
    - `pet_profile_history` (반려동물 프로필 변경 이력)
    - `product_groups` (용량 다른 같은 상품 묶음)
    - `behavior_events` (사용자 조회/장바구니/구매 행동 로그)
    - `dataset_generation_runs` (목데이터 생성 기록 — AI가 채워줄 자리만 마련)
    
    **② 주문(orders/order_items) 테이블 설계 시 AI팀 요구사항**
    
    - 일반구매/구독구매 구분 컬럼 필요 (`purchase_type`: ONE_TIME/SUBSCRIPTION)
    - 취소/반품 수량을 각각 별도 컬럼으로 기록해야 함
    - 구매 당시 시점 기준 정보(카테고리, 상품 용량 등)를 스냅샷으로 저장해야 함 — 나중에 상품 정보가 바뀌어도 "그때 기준"이 보존되도록
    
    **③ AI가 알아서 만들어서 줄 것 (백엔드는 받기만 하면 됨)**
    
    - 상품 286건 + 영양성분 데이터 (SQL 파일로 전달 예정)
    - 알레르기/원료 마스터 데이터
    - 재구매예측 결과 저장 테이블(`repurchase_predictions`) — AI가 계산해서 넣을 테이블, 구조만 미리 맞춰두면 됨
    
    **④ 확인/결정해서 답해줘야 하는 것**
    
    - 다견/다묘일 때 `order_items.pet_id` 처리 방식
    - pgvector 확장 쓸지 (상품/리뷰 임베딩 저장용 — 이건 인프라/DB 설정에도 영향줘서 확인 필요)
    
    **⑤ reviews 테이블 필드 추가**
    
    - `usage_scope`(사용 범위: 내부용/오픈라이선스/사용자생성)
    - `data_origin`(REAL vs SYNTHETIC 구분)
    - `source_site`, `source_review_id`(외부 수집 리뷰면 출처 기록)
    
    **⑥ DB 제약조건 - 8번 섹션 "주요 제약조건·인덱스”**
    
    - orders: PAID면 paid_at null 금지
    - order_items: 취소+반품 수량 합이 quantity 초과 금지
    - reviews: 같은 출처·같은 리뷰 중복 수집 방지 UNIQUE
    
    **⑦ 남은 확정 요청사항**
    
    - 리뷰 허용 출처·수집 범위 (⑤와 연결)
    - recommendation_runs/items 영구 저장 여부
    - 구독(subscription_id) 연동 방식
    - 할인/프로모션 저장 단위
    
    **⑧ 영양분석 API 관련**
    
    - `POST /v1/feeds/analyze` 요청/응답 형식(enum, null 처리, 에러 응답)을 영양 파트와 확정
    - 이건 테이블이 아니라 **API 명세를 영양 AI 파트와 맞추는 작업**이라, 지금까지의 "스키마" 작업과 결이 달라요
