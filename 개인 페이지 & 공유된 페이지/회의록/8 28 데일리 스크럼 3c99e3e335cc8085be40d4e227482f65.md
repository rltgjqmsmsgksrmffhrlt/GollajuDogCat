**데일리 스크럼 이후 추가 전달사항**

- 프론트엔드 전달 사항
    
    **프론트엔드 요청사항 — 결제 · 소셜 로그인 · 사진 저장**
    
    작성: 프론트엔드 · 2026-08-28
    
    - 결제 관련
        
        프론트는 결제위젯 렌더 → 결제 요청 → 리다이렉트 수신까지 맡습니다.
        
        ```
        [프론트]  위젯 렌더, 금액 설정
        [프론트]  결제 요청 직전 → ① 결제 준비 API 호출
        [프론트]  requestPayment() → 토스 결제창
        [토스]    successUrl?paymentKey=&orderId=&amount=&paymentType=
        [프론트]  받은 값 그대로 → ② 결제 승인 API 호출
        [프론트]  결과에 따라 결제완료 화면 / 실패 화면
        ```
        
        ### **요청**
        
        |  API | 프론트가 보내는 값 |
        | --- | --- |
        | ① 결제 준비 | `orderId`, `amount` |
        | ② 결제 승인 | `paymentKey`, `orderId`, `amount` |
        
        ### **확인 부탁**
        
        - orderId 발급 주체: 백엔드에서 내려주시는 게 편합니다
        - 결제 실패 시 에러 코드를 프론트가 그대로 표시할지, 문구로 매핑해 주실지
        - 취소·환불 API 범위
        
        ### **참고**
        
        - 테스트 키로 진행합니다
        - 결제수단 선택 UI는 토스 위젯이 그립니다.프론트에서 카드사 목록·할부 개월을 만들지 않습니다
    - 소셜 로그인 관련
        - Spring Security가 리다이렉트까지 처리하고 프론트는 이동·콜백만 맡는 방식에 동의합니다.
        
        **확인 부탁**
        
        - ① 토큰 전달 방식
            
            `httpOnly` 쿠키 / 리다이렉트 쿼리 중 어느 쪽인가요. 쿠키면 CORS `credentials`와 `SameSite` 설정을 맞춰야 합니다.
            
        - ② 신규 회원 구분 값
            
            첫 방문이면 약관 동의 화면으로, 기존 회원이면 메인으로 보내야 합니다. 콜백 응답에 구분할 값이 필요합니다.
            
        - ③ 콜백 경로
            
            성공·실패 시 프론트의 어느 경로로 돌려보내실지.
            
        - ④ WebView 앱 세션 전달
            
            구글이 WebView 안에서 OAuth를 차단해(`disallowed_useragent`) 앱에서는 외부 브라우저를 열어야 합니다. 외부 브라우저와 앱 WebView는 쿠키를 공유하지 않아, 쿠키 방식이면 로그인 후 앱에 상태가 반영되지 않습니다. 앱으로 돌아올 때 토큰을 전달할 경로가 따로 필요합니다.
            
    - 사진 저장
        - 2안(백엔드에서 S3까지 관리)에 동의합니다.
        - 이미지를 저장 API에서 함께 받아 주시면 좋겠습니다. - 리뷰·프로필·문의 저장 요청 하나에 `multipart/form-data`로 파일을 같이 보내는 형태입니다. - 업로드 API와 저장 API가 나뉘면 프론트가 요청을 두 번 보내야 하고, 사용자가 작성 도중 취소했을 때 이미 올라간 파일을 정리할 방법이 프론트에 없습니다.
        
        **확인 부탁**
        
        | 항목 | 질문 |
        | --- | --- |
        | 제한 | 최대 용량, 장수 |
        | 형식 | `jpg` `png` `webp` `heic` 중 허용 범위 |
        | HEIC | 아이폰 기본 촬영 형식입니다. 변환을 어느 쪽에서 할지 |
        | 리사이즈 | 썸네일 생성 여부 |
        | 응답 | URL 하나인지, 원본·썸네일 여러 개인지 |
        
    - 주소 검색 관련
        - 디자인팀 요청으로 화면을 직접 만들게 되어 행정안전부 도로명주소 API 를 쓰기로 했습니다.
        - 승인키가 1 시스템 1개이고 노출 시 교체해야 해서 백엔드에서 프록시해 주실 수 있는지 확인 부탁드립니다. 배송지 저장도 백엔드에서 하니 함께 가면 좋을 것 같습니다.
