**1. 조사하신 내용 확인**

**1-1. 맞습니다.** Expo SDK 57.0.15 + React Native 0.86.2 기반 WebView 하이브리드 앱입니다. `react-native-webview` 13.16.1로 웹 서비스를 감싸는 구조이고, 현재 네이티브 화면은 없습니다.

다만 네이티브 셸이라 점검 범위에 WebView 설정과 딥링크가 포함됩니다. 참고하시라고 현재 값을 함께 드립니다. WebView에 명시적으로 넘기는 옵션이 없어 대부분 라이브러리 기본값입니다.

```
javaScriptEnabled          : true                  (기본값)
originWhitelist            : http://*, https://*   (기본값)
thirdPartyCookiesEnabled   : true                  (기본값)
setSupportMultipleWindows  : true                  (기본값)
saveFormDataDisabled       : false                 (기본값)
allowFileAccess            : false
mixedContentMode           : NEVER_ALLOW
딥링크 스킴                 : golajugaenyang://     (BROWSABLE)
JS 브리지                   : 미사용 (onMessage / injectedJavaScript 없음)
```

점검 결과에 따라 `originWhitelist` 제한 등 조정할 부분 있으면 알려주시면 반영하겠습니다.

**1-2. 맞습니다.** WebView 사용합니다.

**2. 요청하신 정보**

```
minSdkVersion     : 24   (Android 7.0)
targetSdkVersion  : 36   (Android 16)
compileSdkVersion : 36
ndkVersion        : 27.1.12297006
buildToolsVersion : 36.0.0
packageName       : com.golajugaenyang.app
```

프로젝트에 별도 오버라이드가 없어 Expo/RN 기본 카탈로그 값을 그대로 씁니다. 코드만 보고 답변드리면 부정확할 수 있어 실제로 빌드해서 산출된 APK로 대조했습니다.

```
A: android:minSdkVersion=24
A: android:targetSdkVersion=36
```

**2-4. 가능합니다.**

Android 7.0부터 앱이 사용자 설치 CA를 신뢰하지 않는데 저희 minSdk가 24라 대상 기기 전부가 해당해서, Burp CA를 설치하셔도 HTTPS가 핸드셰이크에서 끊겼을 겁니다.

Network Security Config를 `<debug-overrides>`로 넣어 디버그 빌드에서만 사용자 CA를 신뢰하도록 했습니다. 빌드 타입별 동작은 이렇습니다.

```
debug   : debuggable=true,  networkSecurityConfig 적용,  cleartext 허용
release : debuggable 없음,   <debug-overrides> 무시,      cleartext 차단
```

릴리스 빌드도 설정 파일을 참조하지만 `debuggable` 속성이 없어 Android가 `<debug-overrides>` 블록을 무시합니다. 안드로이드가 이 용도로 제공하는 장치라 운영 빌드가 영향받을 여지는 없습니다. 실제 릴리스 매니페스트로 확인했습니다.

관련 PR입니다 — [https://github.com/urineun-jigeum-bildeujung/mobile/pull/10](https://github.com/urineun-jigeum-bildeujung/mobile/pull/10)
