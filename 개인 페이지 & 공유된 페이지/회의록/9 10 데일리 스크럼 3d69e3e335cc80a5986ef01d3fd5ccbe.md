**백엔드 오전 데일리 스크럼**

- BaseTimeEntity 타입 변경
    
    ```json
    org.springframework.dao.InvalidDataAccessApiUsageException
    Caused by: java.lang.IllegalArgumentException: Cannot convert unsupported date type java.time.LocalDateTime to java.time.OffsetDateTime; 
    Supported types are [java.time.LocalDateTime, java.time.LocalDate, java.time.LocalTime, java.time.Instant, java.util.Date, java.lang.Long, long]
    ```
    
    ```java
    @Getter
    @MappedSuperclass
    @EntityListeners(AuditingEntityListener.class)
    public class BaseTimeEntity {
    
        @CreatedDate
        @Column(name = "created_at", nullable = false, updatable = false)
        private OffsetDateTime createdAt;
    
        @LastModifiedDate
        @Column(name = "updated_at", nullable = false)
        private OffsetDateTime updatedAt;
    }
    ```
    
    - @CreatedDate, @LastModifiedDate가 자동으로 값 채워주는 것이 OffsetDateTime으로의 변환을 지원 안 해준다고 합니다!
    - Instant로 변경하면 될 것 같습니다.
- → OffsetDateTime가 AI 테이블 때문에 그런거라서 여쭤봐야될 듯
- 보안팀 요구사항: 역할별 테스트 계정 필요
    - 사용자는 소셜로그인
    - 관리자 계정은 추후 전달

    - `AI`
        - OffsetDateTime 타입을 다른 타입으로 변경해도 되는지
        - 후보: Instant, LocalDateTime
            
            
            | 구분 | `Instant` (타임존 포함) | `LocalDateTime` (타임존 무관) |
            | --- | --- | --- |
            | **핵심 기준** | 전 세계 어디서 봐도 동일한 절대적 시점이 중요할 때 | 타임존과 무관하게 '달력에 적힌 그 시각'이 중요할 때 |
            | **적용 대상** | 돈, 거래, 이력 등 정확한 시점이 필수인 데이터 | 반복되는 로컬 기준 이벤트/스케줄 |
            | **예시** | 주문 일시, 결제 완료 일시, 배송 시작 일시, 회원 가입일, 이벤트 참여 시간 | 매일 밤 12시(00:00) 정기 핫딜, 지점별 현지 시각 기준 영업 시작 시간(09:00) |
        - FastAPI 관련 전달됐는지 확인 필요
        - 추천 시스템 협의 사항 관련: 추천 응답 캐싱은 AI 응답 캐싱 부탁드립니다
    - `보안`
        - 사용자는 소셜로그인 기반으로 생성, 관리자 계정은 추후 전달
- `AI` 질문 내용은 팀원분들과 공유 후 전달 예정
