# 인증/암호화/보안통제/정책통합

### 1. 인증 (Authentication)

- **관리자 접근**: EKS API는 Private Endpoint로 구성하고, 관리자는 Tailscale을 통해 내부망에 진입한 뒤 IAM 기반 EKS Access Entry로 접근
- **CI/CD 인증**: GitHub Actions는 장기 Access Key 대신 GitHub OIDC + AWS STS 임시 자격증명 사용
- **워크로드 인증**: AWS 리소스에 접근하는 Kubernetes Workload는 EKS Pod Identity를 사용하고 ServiceAccount별 IAM Role 분리
- **시크릿 접근**: AWS Secrets Manager를 원본으로 사용하고 External Secrets Operator를 통해 필요한 Namespace에만 Secret 전달

### 2. 암호화 (Encryption)

- **외부 통신**: Route53 + ACM + ALB를 이용한 HTTPS/TLS 구성
- **저장 데이터**: S3, ECR, EBS 등 저장 데이터에 서버 측 암호화 적용
- **S3 전송 보호**: HTTPS가 아닌 요청은 Bucket Policy로 차단
- **민감정보 보호**: JWT Private Key, 내부 Secret 등을 Git이나 tfvars에 저장하지 않고 Secrets Manager/SSM으로 관리

### 3. 보안 통제 (Security Controls)

- **네트워크 분리**: EKS Worker와 관리용 Router를 Private Subnet에 배치하고 Backend Service는 ClusterIP로 구성
- **IAM 권한 분리**: Jenkins, ESO, CNPG, Karpenter 등 Workload별 IAM Role 분리
- **이미지 보안**: CI에서 Trivy 취약점 검사를 수행하고 기준 이상 취약점 발견 시 배포 차단
- **구성 변경 통제**: Terraform과 GitOps를 기준으로 인프라/Kubernetes 설정을 관리하고 Argo CD selfHeal로 수동 변경 복구
- **백업**: CNPG DB Backup을 S3에 저장하고 Versioning 및 보존 정책 적용

### 4. 현재 추가 적용이 필요한 항목

- Service 간 HTTP, Kafka, Redis 등 **내부 통신 TLS/인증 미적용**
- **NetworkPolicy 기본 적용 및 Egress 제어 미완료**
- Terraform Role 등 일부 **IAM 권한 최소화 추가 필요**
- **CloudTrail, EKS Audit Log, VPC Flow Log 등 감사 로그 추가 적용 필요**
