# 추천 시스템

## 1. 엔드포인트 목록

| 엔드포인트 | Method | 용도 |
| --- | --- | --- |
| `/recommend/home` | GET | 콜드스타트 추천 (홈 화면) |
| `/recommend/substitute` | GET | 대체상품 추천 |
| `/recommend/exclusions` | GET | 역추천(제외 이유) |

## 2. 공통 요청 파라미터

| 파라미터 | 필수 | 설명 |
| --- | --- | --- |
| `pet_id` | 필수 | 반려동물 ID |
| `product_id` | substitute/exclusions 시 필수 | 기준 상품 ID |
| `cart_items` | cross-sell 시 필수 | 장바구니 상품 ID 배열 |

## 3. 공통 응답 형식

```json
{
  "pet_id": "pet_123",
  "reason_type": "SUBSTITUTE",
  "items": [
    {
      "product_id": "prod_456",
      "rank": 1,
      "score": 0.82,
      "confidence": "HIGH",
      "match_level": 2,
      "reason_text": "소형견 보호자 82%가 만족했어요"
    }
  ],
  "excluded": [
    { "product_id": "prod_789", "reason_code": "ALLERGY_CONFLICT", "reason_text": "..." }
  ],
  "generated_at": "2026-08-18T12:00:00Z"
}
```

- `confidence`: `HIGH` / `MEDIUM` / `LOW`
- `match_level`: 1~4 또는 `null` (cross-sell은 항상 null)
- `excluded`는 요청 상품이 제외 대상일 때만 채워짐 (평소엔 빈 배열)

## 4. 에러 응답

| 상태코드 | 상황 |
| --- | --- |
| 400 | 필수 파라미터 누락 |
| 404 | `pet_id`/`product_id` 존재하지 않음 |
| 200 + `items: []` | 추천 후보 없음(에러 아님, 정상 응답) |

## 5. 갱신 주기 (참고)

- 임베딩·인기도·리뷰 매칭 스코어: **배치 1일 1회 갱신** → API는 조회만 하므로 응답속도 빠름
- 역추천(`/recommend/exclusions`)만 예외: **실시간 조회**, 캐시 미사용 (안전 문제라 결제 전 재검증 필요)

## 6. 협의 필요 사항

- 실제 배포 base URL, 인증 방식(JWT 등 기존 API 컨벤션 따름 예정)
- 응답 캐싱(Redis) 위치 — AI 서버 자체 캐싱 vs 백엔드 게이트웨이 캐싱
- `/recommend/exclusions` 응답 속도 SLA (실시간 조회라 다른 엔드포인트보다 느릴 수 있음)
