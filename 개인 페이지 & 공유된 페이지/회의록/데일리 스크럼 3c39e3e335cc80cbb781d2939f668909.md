#### 백엔드

- (프론트엔드) 응답 포맷 관련
    - 논의 내용
        
        **성공 응답 예시 A ← A 응답으로 확정**
        
        ```json
        { "id": 1, "name": "홍길동" }
        ```
        
        - 데이터 바로 반환
        
        **성공 응답 예시 B**
        
        ```json
        {
          "message": "요청이 성공적으로 처리되었습니다.",
          "data": { "id": 1, "name": "홍길동" },
          "error": null,
          "timestamp": "2026-08-19T05:00:00Z"
        }
        ```
        
        - 데이터 data 안으로, 기타 정보들이 포함되어 반환된다.
        
        → 이렇게 데이터 외 필요 정보들이 있는지
        
        **실패 응답 예시 ← 응답 예시 형태로 확정**
        
        ```json
        {
          "type": "about:blank",
          "title": "Member Not Found",
          "status": 404,
          "detail": "회원을 찾을 수 없습니다.",
          "instance": "/api/members/1",
          "errorCode": "MEMBER_404",
          "traceId": "b3c1...",
          "timestamp": "2026-08-19T05:00:00Z"
        }
        ```
        
    
    추후에 응답에 관련된 GlobalMessage 처리는 팀장(전지호)가 해두겠습니다!
    
    - (프론트, 인프라, PD?) 이미지 저장 관련
        - 생각한 방법
            - 사진 등록 별도로 → S3 url 프론트에서 잠깐 저장
            - 실제 등록 요청을 보낼 때 받아놓은 url 포함해서 전송
            - 프론트엔드 관점에서는 어떤 방식을 예상하고 있는지 궁금
                - 프론트엔드 측도 백엔드 팀장님이 말씀 주신 플로우대로 가면 될 것 같다고 이야기드렸음
