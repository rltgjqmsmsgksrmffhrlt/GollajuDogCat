`PM` 

1. 자체 회원가입이 없어서 해당 화면에는 카카오, 구글 버튼만 존재해야 될 것 같습니다. 
버튼을 누르는 행위 자체는 초기 회원가입과 로그인 모두 동일함.
    
    초기 회원가입) 카카오 버튼 클릭 → 소셜 로그인 후 성공 → 약관동의
    이후 로그인 ) 카카오 버튼 클릭 → 소셜 로그인 후 성공 → 메인화면
    
    ```markup
    맞습니다! 
    기능 상으로는 sns 로그인 (이전에 합의 했던 카카오, 구글)만 가능하고 
    나머지는 그냥 나중에 MVP를 위한 목업으로 기능은 없는 그냥 UI라고 생각해주시면 될 것 같습니다!
    ```
    

![image.png](9%2002%20%EB%8D%B0%EC%9D%BC%EB%A6%AC%EC%8A%A4%ED%81%AC%EB%9F%BC/image.png)

1. 회원가입 흐름과 회원정보를 받는 흐름이 나누어져 있는 게 맞을까요?
    
    소셜로그인 성공 → 사용자용 약관 동의 → 가입완료
    
    마이페이지 → 이름, 생일, 전화번호 기입, 랜덤닉네임 수정
    
    ```markup
    맞습니다!! 다만 소셜 로그인 성공하고 사용자용 약관 동의 이후 사용자 이름 (또는 닉네임)을 입력 받아야 합니다. 
    현재 이름을 받을지, 닉네임을 받을 지는 PD측과 논의 중입니다!
    2-1. 닉네임을 받는 경우: 사용자가 닉네임을 적지 않으면, 랜덤 닉네임으로 저장-> 마이페이지 내 랜덤 닉네임 수정 
    2-2. 닉네임 삭제, 이름으로만 받을 경우: 마이페이지 내 닉네임 수정 부분 삭제 
    2-3. 닉네임 & 이름 모두 받는 경우: 
    이름: 소셜 로그인 내 데이터에서 가져올 수 있다면, 입력X/만약 그렇지 않다면 입력해야 함
    닉네임: 2-1과 동일
    
    ```
